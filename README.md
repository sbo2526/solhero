# SolHero — مرورگر مهمان تک‌حسابی

مرورگر پایدار و پنل کنترل دستی برای ساخت **یک شخصیت جدید بدون کیف‌پول** از لینک دعوت:

https://play.playsolhero.com/?ref=RAN7TJA

**وضعیت واقعی:** کد زیرساخت آماده است؛ هنوز به Railway مستقر نشده، حساب بازی ساخته نشده و ثبت دعوت تأیید نشده است. این برنامه بات بازی‌کن نیست و به‌صورت خودکار شخصیت نمی‌سازد، قوانین را قبول نمی‌کند، کلیک نمی‌کند، خرید نمی‌کند و کیف‌پول متصل نمی‌کند.

## نحوه کار

- یک Chromium با profile پایدار اجرا می‌شود.
- اولین navigation موفق HTTP شامل `?ref=RAN7TJA` است؛ بازدیدهای بعدی صفحه اصلی را با همان profile باز می‌کنند.
- فایل `initial-navigation.json` فقط ارسال لینک را ثبت می‌کند، **نه ایجاد حساب یا پذیرفته‌شدن دعوت**.
- از طریق پنل فارسی رمزدار، تصویر مرورگر را می‌بینید و شخصاً کلیک و تایپ می‌کنید.
- بازکردن همین پنل در چند دستگاه، همان مرورگر سرور را کنترل می‌کند. کنترل هم‌زمان از چند دستگاه توصیه نمی‌شود.
- خطای راه‌اندازی یا بسته‌شدن مرورگر موجب تلاش مجدد با backoff می‌شود. وضعیت داخلی اتصال خود بازی و پذیرش نشست از طرف سرور بازی هنوز تشخیص داده نمی‌شود.
- تصویر پنل قابل کلیک است؛ برای تایپ، ابتدا فیلد داخل تصویر را کلیک کنید، سپس متن را از فرم زیر تصویر بفرستید.

## استقرار روی Railway

1. تغییرات این مخزن باید روی همان branch متصل به پروژه Railway منتشر شده باشند. ایجاد pull request به معنی استقرار روی Railway نیست.
2. از مخزن یک سرویس Railway بسازید. `Dockerfile` و `railway.toml` موجودند؛ start command سفارشی لازم نیست.
3. یک **Volume** به همین سرویس با mount path برابر **`/data`** وصل کنید. بدون Volume، حفظ حساب در deploy/restart قابل اتکا نیست.
4. متغیرها را در بخش Variables تنظیم کنید:

   | متغیر | مقدار |
   | --- | --- |
   | `DASHBOARD_PASSWORD` | رمز تصادفی و منحصربه‌فرد با حداقل ۲۰ کاراکتر؛ خودتان در Railway وارد کنید، نه در چت یا Git |
   | `REFERRAL_CODE` | `RAN7TJA` |
   | `DATA_DIR` | `/data` |
   | `RAILWAY_RUN_UID` | `0` برای اجازه آماده‌سازی Volume؛ entrypoint جدید قبل از اجرای Node و Chromium دسترسی را به کاربر غیرروت `node` کاهش می‌دهد |

   `PORT` را Railway تعیین می‌کند. مقدار نمونه خالی رمز در `.env.example` عمداً اجازه اجرا نمی‌دهد.
5. تعداد replica را **۱** نگه دارید و **Serverless را خاموش کنید**. این مورد به‌صورت دستی در تنظیمات Railway بررسی شود؛ فایل TOML فقط یک replica و restart policy را تنظیم می‌کند.
6. یک public domain با HTTPS بسازید. healthcheck عمومی `/healthz` فقط زنده‌بودن HTTP server را می‌سنجد، نه آماده‌بودن بازی یا ثبت حساب.
7. آدرس پنل را باز کنید. نام کاربری **`solhero`** و رمز همان `DASHBOARD_PASSWORD` است. فقط روی HTTPS از آن استفاده کنید.
8. وقتی صفحه بازی در تصویر ظاهر شد، قوانین را بخوانید و خودتان شخصیت جدید را بسازید. نام و کلاس را داخل بازی انتخاب کنید؛ نیازی به ارسال اطلاعات حساس در چت نیست.
9. قبل از ادامه، **داخل خود بازی تأیید دعوت‌کننده/کد دعوت را بررسی کنید**. اگر قابل مشاهده نیست از پشتیبانی بازی تأیید بگیرید؛ کد در پنل فقط مقدار پیکربندی‌شده است.
10. یک restart واقعی انجام دهید و تأیید کنید همان شخصیت برمی‌گردد. اگر برگشت به ایجاد شخصیت مشاهده شد، ادامه ندهید و حساب دوم نسازید؛ ابتدا پایداری نشست بررسی شود.

### رفع خطای مجوز Volume

Volume بعد از Build متصل می‌شود؛ بنابراین `chown` زمان Build به‌تنهایی مالکیت Volume واقعی را اصلاح نمی‌کند. entrypoint جدید هنگام شروع کانتینر، فقط روی Volume اختصاصی `/data` مالکیت را به `node` تغییر می‌دهد و سپس با `gosu` برنامه را به‌عنوان کاربر غیرروت اجرا می‌کند. فایل‌های پروفایل و marker حذف یا بازنشانی نمی‌شوند و symlinkهای داخل Volume برای تغییر مالکیت پیمایش نمی‌شوند.

برای دریافت اصلاح، آخرین کامیت را از شاخه متصل به Railway **Build و Deploy** کنید؛ Restart تصویر قدیمی کافی نیست. `DATA_DIR=/data`، مسیر mount برابر `/data` و `RAILWAY_RUN_UID=0` باشد و entrypoint پیش‌فرض Docker را دور نزنید. پس از آماده‌سازی باید این خط در لاگ دیده شود:

```text
Storage ownership prepared; starting application as non-root node user.
```

از Volume اختصاصی همین برنامه استفاده کنید؛ دادهٔ سرویس‌های دیگر را در `/data` قرار ندهید. در صورت فقط‌خواندنی‌بودن Volume یا شکست تغییر مالکیت، کانتینر بدون اجرای مرورگر به‌صورت root متوقف می‌شود. این آماده‌سازی در تست‌ها با ابزارهای شبیه‌سازی‌شده بررسی شده است؛ اجرای واقعی روی Railway باید تأیید شود.

### نکته‌های مهم

- بازکردن لینک دعوت روی موبایل یا لپ‌تاپ شخصی، لزوماً همان حساب مهمان روی سرور نیست. برای همین حساب، از پنل سرور استفاده کنید.
- بعد از ساخت حساب، Volume، پوشه `profile` یا فایل marker را پاک نکنید. گزینه reset/create-new در پنل عمداً وجود ندارد.
- کد referral بعد از اولین بازدید، با تغییر متغیر محیطی دوباره روی حساب موجود اعمال نمی‌شود؛ امکان تغییر دعوت‌کننده ادعا نشده است.
- guest account ممکن است برای بازیابی به داده‌های مرورگر متکی باشد. بدون کیف‌پول، از دست رفتن نشست ممکن است به معنی از دست رفتن دسترسی باشد. سازوکار بازیابی بازی هنوز تست نشده است.
- Playwright profile معمولاً cookie/localStorage/IndexedDB را نگه می‌دارد؛ نگهداری sessionStorage یا نشست منقضی‌شده تضمین نمی‌شود. تست restart ضروری است.
- اجرای Chromium و Volume هزینه دارد. CPU/RAM و بودجه را از مصرف واقعی تنظیم کنید؛ عدد تضمینی برای هزینه یا منابع وجود ندارد.
- روشن‌بودن کانتینر یا تب، تضمین آنلاین‌شناخته‌شدن توسط بازی یا پیشرفت بدون توقف نیست.
- این نسخه برای drag، چندلمسی، صدای زنده، آپلود فایل یا اتصال کیف‌پول طراحی نشده است؛ popupها و downloadها بسته‌اند.

## امنیت

- کلید خصوصی، seed phrase، PIN و فایل نشست را به Git یا چت نفرستید.
- پروفایل مرورگر و backupهای Volume اطلاعات حساس حساب‌اند؛ دسترسی محدود نگه دارید.
- پنل با HTTP Basic Auth محافظت می‌شود و باید پشت HTTPS Railway باشد. endpointهای کنترل به Origin یکسان و header اختصاصی نیاز دارند؛ مرورگر فقط navigation اصلی به دامنه بازی را قبول می‌کند.
- رمز پنل دسترسی به بازی می‌دهد؛ آن را به دیگران ندهید. برای ابطال دسترسی رمز را تغییر دهید و redeploy کنید. Basic Auth دکمه logout ندارد؛ برای خروج از دستگاه اشتراکی تمام پنجره‌های آن مرورگر را ببندید یا از حالت خصوصی استفاده کنید.
- Chromium در این پیکربندی Playwright بدون sandbox داخلی اجرا می‌شود. کانتینر را سرویس ایزوله بدون کلید کیف‌پول و بدون دسترسی به دیگر سرویس‌های حساس نگه دارید؛ این جایگزین ارزیابی امنیتی کامل نیست.
- تصویربرداری دوره‌ای فقط وقتی پنل باز است انجام می‌شود؛ هیچ کلیک یا فعالیت مصنوعی زمان‌بندی‌شده‌ای وجود ندارد.

## عیب‌یابی «در انتظار تلاش مجدد»

این وضعیت یعنی HTTP server پنل فعال است، ولی آماده‌سازی داده، اجرای Chromium یا بازکردن بازی کامل نشده است. در نسخه جدید، پنل رمزدار و Deploy Logs یک کد خطای امن، مرحله و زمان را نشان می‌دهند؛ متن خام Playwright، URLها و اطلاعات نشست نمایش داده نمی‌شوند.

| کد | بررسی پیشنهادی |
| --- | --- |
| `DATA_PERMISSION` | مجوز Volume و `DATA_DIR`؛ برای Volume با مالک root مقدار `RAILWAY_RUN_UID=0` و Deploy جدید |
| `DISK_FULL` / `DATA_READ_ONLY` | ظرفیت و قابل‌نوشتن‌بودن Volume؛ پروفایل را پاک نکنید |
| `CHROMIUM_MISSING` / `CHROMIUM_DEPENDENCIES` | Build از Dockerfile این مخزن، نه Railpack خام |
| `PROFILE_IN_USE` | فقط یک replica؛ توقف نمونه قبلی را بررسی کنید، فایل‌های قفل را خودکار حذف نکنید |
| `GAME_DNS` / `GAME_NETWORK` / `GAME_TIMEOUT` / `GAME_TLS` | شبکه خروجی، DNS، TLS و وضعیت سایت بازی |
| `GAME_HTTP_403` یا کد HTTP دیگر | سایت پاسخ خطا داده؛ این برنامه محدودیت دسترسی یا ضدبات را دور نمی‌زند |
| `CHROMIUM_EXITED` | لاگ‌های crash و نمودار RAM؛ کمبود حافظه فقط یکی از احتمال‌هاست |

اگر هنوز تنها متن قدیمی «در انتظار تلاش مجدد» را می‌بینید، آخرین کامیت شاخه متصل به سرویس را Deploy و صفحه پنل را Refresh کنید. برای بررسی، فقط کد، مرحله و پیام امن را ارسال کنید؛ نه رمز پنل یا پروفایل حساب. `/healthz` همچنان فقط سلامت HTTP را گزارش می‌دهد.

## اجرای محلی و تست

نیازمند Node.js 22 یا جدیدتر:

```bash
npm ci
npx playwright install --with-deps chromium
cp .env.example .env
# رمز منحصربه‌فرد با حداقل ۲۰ کاراکتر را خودتان در .env تنظیم کنید.
node --env-file=.env src/index.js
```

پنل روی `http://localhost:3000` است؛ این فقط برای تست محلی روی دستگاه خودتان است. روی سرور عمومی از HTTPS استفاده کنید. برنامه روی `0.0.0.0` گوش می‌دهد، بنابراین پورت محلی را به شبکه نامطمئن باز نگذارید.

```bash
npm test
npm run check
```

۳۵ تست خودکار: احراز هویت، CSRF، اعتبارسنجی عملیات، عدم نشت خطا، صف عملیات، مسیر referral/profile در restart، دسته‌بندی خطاها، پاک‌شدن خطا پس از بازیابی، حفظ پروفایل در retry و مسیرهای آماده‌سازی Volume و کاهش سطح دسترسی با فرمان‌های سیستمی شبیه‌سازی‌شده. تست‌های مرورگر از launcher شبیه‌سازی‌شده استفاده می‌کنند؛ **موفقیت تست‌ها به معنی تست Chromium واقعی، Docker، Railway یا بازی نیست**. این موارد در محیط فعلی اجرا نشده‌اند.
